# Lucent Encrypt — spec (draft, LucentEncrypt/1)

A demonstration of public-key encryption that needs nothing installed and nothing stored. A person's key pair is derived from a **phrase of 7 words** plus an **identifier** (name, phone or e-mail). They publish a **public link**; anyone can use it to encrypt a short text message for them; only the phrase opens it. Three modes show the cost of post-quantum security side by side: **X25519** (classic), **ML-KEM-768** (post-quantum) and **X-Wing** (hybrid of both).

No server is involved: everything runs in one self-contained page and travels in links. Interface language is Portuguese; terms in *italics* are the interface words. Where this document says MUST, the behavior affects compatibility or security. **Every parameter in sections 2–4 is part of the format: changing one changes every key, so it needs a new version.**

## 1. Flow

| Tab | What happens |
|---|---|
| *Criar minha chave* | Enter the identifier; *Gerar frase* (or *Já tenho uma frase*); choose the mode; the page derives the key and shows the public link, its fingerprint, and *Copiar*, *QR*, *Enviar pelo WhatsApp*, *Enviar por e-mail*. |
| *Cifrar para alguém* | Opening a public link (`#k=…`) lands here: *Cifrar para MARIA SILVA · modo híbrido · 7K3M-QX9R-2HDA-W5TB*. Type the message (at most 2,000 characters); *Cifrar*; the encrypted link (`#m=…`) with *Copiar*, *Enviar pelo WhatsApp*, *Enviar por e-mail*. |
| *Abrir* | Opening an encrypted link lands here: *Mensagem para MARIA SILVA · modo híbrido*. Type the phrase; *Abrir*; the text. |

- **Making the public link again.** The same phrase and identifier always give the same key, in each mode. A person can therefore publish up to three public links (one per mode) from one phrase, each labelled with its mode.
- **Encrypting.** The sender chooses nothing: the page uses the mode of the recipient's link.
- **Opening.** The identifier comes from the encrypted link; only the phrase is typed.
- **Comparison panel.** On *Criar* and *Cifrar*, a small table shows the real size of the public link and of the encrypted link in all three modes, for the current identifier and message.
- **Link to Segredo:** *Divida sua frase entre pessoas de confiança.*

## 2. Phrase and identifier (MUST)

**Phrase.**
- 7 words from the Portuguese BIP39 word list: 2,048 words without accents, each identified by its first four letters. That gives 7 × 11 = 77 bits.
- Generated by the page with `crypto.getRandomValues`. *Já tenho uma frase* accepts 7 words typed in.
- **Input.** Case-insensitive, accents removed, words split on spaces, commas or line breaks. A word is accepted when its first four letters match exactly one list word, and is completed to that word.
- **Instant check.** A word that matches no list word is highlighted at once (*“casx” não está na lista*), and so is a wrong number of words. This reveals nothing about the key.
- **No checksum.** There is no check word and no stored hash of the phrase. A fast check would let an attacker discard wrong guesses without paying for the slow derivation of section 3.
- **Canonical phrase:** the 7 full list words, lowercase, joined by single spaces.

**Identifier** (it becomes the salt). It is normalized, and the page shows the result (*identificador: 5531999990000*):
- **E-mail** (contains `@`): spaces removed, lowercase.
- **Phone** (only digits, spaces and `+ ( ) - .`, with 10 or more digits): digits only; `55` is prepended when 10 or 11 digits are given.
- **Name** (anything else): NFKD, combining marks removed, uppercase, runs of spaces become one space, trimmed.
- At most 128 bytes after normalization. It must not be empty.

The identifier appears in the public link and in every encrypted link. The page says so: *O identificador fica visível em todos os links. Use um nome se não quiser expor telefone ou e-mail.*

## 3. Key derivation (MUST)

```
salt  = SHA-256("LucentEncrypt/1/salt" ‖ 0x00 ‖ identifier)
k     = Argon2id(password = canonical phrase, salt, m = 65,536 KiB (64 MiB), t = 3, p = 1, length 32)
seed  = HMAC-SHA-256(k, "LucentEncrypt/1/" ‖ mode)        mode ∈ {"x25519", "mlkem768", "xwing"}
```

- **x25519:** `sk = seed` (clamped as usual), `pk = X25519(sk, 9)`, 32 bytes.
- **mlkem768:** `(d, z) = SHA-512(seed)` split into two 32-byte halves; `(pk, sk) = ML-KEM-768.KeyGen_internal(d, z)` (FIPS 203). `pk` is 1,184 bytes.
- **xwing:** `(pk, sk) = X-Wing.DeriveKeyPair(seed)` per draft-connolly-cfrg-xwing-kem (ML-KEM-768 + X25519). `pk` is 1,216 bytes.

Each mode has its own seed, so the three keys are unrelated even though they come from the same phrase.

Argon2id runs in WebAssembly (hash-wasm, MIT), built into the page, so it works offline. The target is 2–3 s on a mid-range phone. The page shows a progress line while it runs (*Derivando a chave… isto leva alguns segundos de propósito*).

## 4. Formats (MUST)

All binary, sent as base64url (no padding) after `#` in `https://lucentcrypto.org/encrypt/`. Lengths are big-endian.

**Public link `#k=`:**

```
0x01 (version) · mode (1 = x25519, 2 = mlkem768, 3 = xwing) · len(identifier) (1 byte) · identifier (UTF-8) · pk
```

- **Fingerprint:** the first 80 bits of SHA-256 of the whole binary above, in Crockford Base32, uppercase, in four groups of four: `7K3M-QX9R-2HDA-W5TB`.
- **Decoding the fingerprint** is lenient (case-insensitive, O read as 0, I and L read as 1). There is no check character.
- The page says: *Para ter certeza de que o link é mesmo da pessoa, confira a impressão digital com ela por outro meio (telefone, pessoalmente).*

**Encrypted link `#m=`:**

```
0x01 · mode · len(identifier) · identifier · fingerprint (10 bytes, as above) · kem-ct · aead-ct
```

- **kem-ct:**
  - x25519: the ephemeral public key `E` (32 bytes), with `ss = SHA-256("LucentEncrypt/1/x25519" ‖ X25519(e, pk) ‖ E ‖ pk)`.
  - mlkem768: the ML-KEM-768 ciphertext (1,088 bytes) and its shared secret.
  - xwing: the X-Wing ciphertext (1,120 bytes) and its shared secret.
- **header:** everything before `aead-ct`.
- **AEAD:** `key ‖ nonce = HKDF-SHA-256(ikm = ss, salt = empty, info = "LucentEncrypt/1/aead" ‖ SHA-256(header), length 44)`; then `aead-ct = AES-256-GCM(key, nonce, plaintext, aad = header)`. `ss` is fresh for every message, so a derived nonce is safe.
- **plaintext:** 2-byte length ‖ UTF-8 text ‖ random padding up to a multiple of 64 bytes, which hides the exact length. At most 2,000 characters and 6,000 bytes of text.

## 5. Opening, and the error messages

1. **Format.** Decode, check the version and mode, and read the identifier and fingerprint.
2. **Phrase.** Run the instant checks of section 2.
3. **Derive and compare.** Derive the key (section 3) and recompute the recipient's fingerprint from the identifier and the derived `pk`.
   - Different: *Frase errada.* There is no hint about which word is wrong.
   - The public key is public anyway, so this comparison gives an attacker nothing they don't already have, and every test still costs a full Argon2id.
4. **Decrypt.** Decapsulate and run AES-GCM.
   - Failure: *A mensagem foi alterada ou está incompleta.*
   - Success: the text, with *Copiar* and *Esconder*.

## 6. What it guarantees, and what not (shown on the page)

- **Only the phrase opens it.** No one else can read the message, including LucentCrypto, which never sees anything.
- **Quantum.**
  - x25519: a future quantum computer could read today's messages.
  - mlkem768: designed to resist one.
  - xwing: stays secure as long as either part holds. This is the recommended mode, the default on *Criar*.
- **The phrase is everything.**
  - Lose it and the messages can never be opened.
  - Anyone holding the public link can try to guess it, forever and offline. 77 random bits and a slow derivation make that impractical. A phrase the person chose themself would not be safe, which is why the page generates it.
- **Sender unknown.** The recipient learns nothing about who encrypted a message. There are no signatures.
- **Public links can be faked.** Someone can publish a link in another person's name; the fingerprint, checked through another channel, is the defence.
- **Visible identifier:** the identifier (name, phone or e-mail) can be read in every link.
- **Not protected:** malware on the device; someone watching the phrase being typed; a message that is too long (the limit is 2,000 characters; no files).
- **A danger block** above everything, as in Segredo: *Não use para guardar senhas de bancos, carteiras de criptomoedas ou qualquer coisa de valor. É uma demonstração.* There is also the same *sem garantias* notice.

## 7. Site

- **Page:** `/encrypt/`, one self-contained HTML file. The libraries are built in:
  - noble-curves (X25519);
  - noble-post-quantum (ML-KEM-768, X-Wing);
  - noble-hashes (SHA-2, HMAC, HKDF, SHA-3 for X-Wing);
  - hash-wasm (Argon2id);
  - qrcode-generator;
  - the Portuguese BIP39 word list. Its source and license go in the footer, with no other reference.

  These add about 150 KB. No external requests, so the page works when saved and offline.
- **Site integration:** a card on the home page, the sitemap, and an og image.
- **Tests (Node):**
  - phrase parsing and four-letter completion; identifier normalization; Argon2id with fixed vectors;
  - each mode: key derivation reproducible from phrase and identifier, encrypt and open, wrong phrase vs altered message, link sizes;
  - ML-KEM and X-Wing known-answer tests from their standards, through the library.
- **To confirm while implementing:** the license of the BIP39 word list, and that noble-post-quantum's X-Wing matches the current draft.
