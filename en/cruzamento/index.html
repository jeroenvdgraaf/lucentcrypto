Private list matching

Português

Two organizations want to know which customers, patients or suppliers they have in common, without handing their lists to each other. With private set intersection (PSI), each side learns only what is on both lists, and nothing about the rest of the other’s list.

1Why exchanging hashes of ID numbers is not enough

The most common idea is for each side to send the SHA-256 of each ID number instead of the number itself. Here the ID is the CPF, Brazil’s 11-digit taxpayer number. It protects nothing: there are only about a billion valid CPFs, and whoever receives a hash tries them all until one gives the same result.

      What this demo guarantees, and what it does not

      • Only the agreed result comes out: the intersection, or only its size. The other side’s other records arrive as blinded points, which say nothing without that side’s secret.
      • The sizes are visible: each side learns how many records the other has. That is on purpose: it is what lets you spot a dictionary attack.
      • Dictionary attack: a side can put the identifiers it wants to test into its own list, and any PSI allows that. The defense is to agree on a maximum size beforehand, check the announced size and stop if it makes no sense.
      • Honest but curious sides: the demo assumes each side follows the protocol. Against a side that deliberately deviates from it, stronger versions exist.

      Format LucentPSI/1 · ristretto255. Each identifier becomes a point H(x) through the RFC 9496 map (64 bytes of SHA-512 of “LucentPSI/1”, the session, the profile and the normalized identifier). A blinds with kA, B with kB; each side blinds again what it receives, and kA·kB·H(x) is the same on both sides. Security: decisional Diffie–Hellman, with the hash modelled as a random oracle.
